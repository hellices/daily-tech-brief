DAILY TECH BRIEF: ONE SHORT HTML MESSAGE AT 09:00

The user wants a compact, readable Teams digest, NOT multipart plain-text report contents.
Use only the current user's Teams self-chat ("You" / "나와의 채팅"). The private automation settings specify the approved account.

1. Resolve the destination.
   Call m_m365_status; require the signed-in UPN to match the approved UPN in automation settings.
   Call workiq_create_chat_by_email with that exact email and require chatId="48:notes".
   Do not search recent chats or send to a channel, group, another person, email, or bot.
   Do not change permissions/authentication/settings unattended.

2. Prepare the current day's digest.
   Use the current injected date interpreted in Asia/Seoul.
   Run python3 briefing.py digest --date YYYY-MM-DD.
   It returns content_type="html", message, issue_digest, message_digest, mode and already_sent.
   If already_sent=true, stop without another notification.
   The message is Technical Spotlight, at most3short highlights, and descriptive links. Keep the HTML paragraphs, bold text and bullets exactly as generated.
   Never call the legacy full-report delivery command for routine Teams messages.
   If the current report has a verified publication record, mode=published and links lead to the dated report and its sections.
   If it is not published, mode=preview: direct source links and an honest publication-pending note are used. Never claim an unpublished or stale page is ready.
   Do not make up a dated URL that is not verified. Report content approval still requires the full exact preview in Scout.
   If today's draft is missing or invalid, send only a short HTML paragraph to self-chat:
   <p>오늘의 Daily Tech Brief가 아직 준비되지 않았습니다. 이전 보고서를 대신 보내지 않았습니다.</p>
   Surface the precise operational failure in the private run result, not as raw stack traces in the reader message.

3. Send and record one actual success.
   Use workiq_send_chat_message(chatId=resolvedSelfChat, content=exactMessage, contentType="html").
   Only after a successful response with an actual message ID, run:
   python3 briefing.py record-digest --date YYYY-MM-DD --mode ACTUAL_MODE --message-digest ACTUAL_MESSAGE_DIGEST --message-id ACTUAL_MESSAGE_ID
   Re-run python3 briefing.py digest --date YYYY-MM-DD --mode ACTUAL_MODE and require already_sent=true.
   Preserve old full-report receipts and other revision receipts. Compact digest receipts are separate by revision and preview/published mode.
   If a send succeeds but recording fails, stop and retain the message ID; do not blindly resend.
   If send success is ambiguous or a tool fails, stop and report the exact error privately.
   Do not send an additional automatic summary. teamsNotify=never avoids duplicate notifications.
   A message to self-chat is not a bot command channel; do not claim replying there publishes a report.

4. Publication remains a separate approved operation.
   Show the exact full report preview and its public destination to the user in Scout and wait for approval.
   On approval: python3 briefing.py promote --date YYYY-MM-DD --digest APPROVED_ISSUE_DIGEST --approved.
   Run the existing Python/Node tests and python3 briefing.py build; inspect the intended diff, commit and push only approved public changes.
   Preserve older dates. An explicitly requested same-day overwrite changes the same reports/YYYY-MM-DD.json and the same permalink.
   Wait for successful Pages deployment and verify the dated page's data-issue-digest equals APPROVED_ISSUE_DIGEST.
   Then run python3 briefing.py record-publication --date YYYY-MM-DD --digest APPROVED_ISSUE_DIGEST.
   A confirmed publication can be followed by the compact published-mode digest, using the same send/record steps above.

5. Same-day corrections.
   Prepare schema2 revision=N+1, supersedes=currentDraftDigest, and a short revision_note.
   Use python3 briefing.py revise --file LOCAL_JSON --expected-digest CURRENT_DRAFT_DIGEST.
   This preserves old draft/receipt history and leaves the public file unchanged until the corrected exact preview is approved.
   Never clear state, force-overwrite the draft, or pretend old receipts mean a changed digest was delivered.
